# 04 · 部署与交付

面向「把 XP 客户端装到现场 XP 机器上并用起来」这件事。范围基线见 [00-范围与验收.md](00-范围与验收.md)，
共库约定见 [02-数据契约.md](02-数据契约.md)。

| 交付物 | 位置 | 说明 |
| --- | --- | --- |
| 程序包 | `dist\ORT-XP-<版本>-<日期>.zip` | onedir 目录的压缩包；解压即用，无需安装、无需 Python |
| 程序目录 | `dist\ORT-XP\` | 含 `ORT-XP.exe`、`MSVCR100.dll`、tcl/tk、`selftest.cmd`、`make_shortcut.vbs`、`reminder.cmd` |

```powershell

```

## 2. 目标机要求

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows XP SP3（32 位）；也验证过在 Windows 10 上直接运行 |
| 运行库 | **不需要**另装：VC++2010 运行库（`MSVCR100.dll`）、tcl/tk、sqlite3 都在包内 |
| 磁盘 | 约 100 MB（程序 15 MB + 日志与缓存） |
| 数据 | 一个含主程序生成的 `ort_plans.db` 的**数据文件夹**；SQLite 打不开 UNC，路径必须映射成盘符 |
| 网络 | 数据文件夹在网络共享上时，XP 与主程序要能在同一网段互通；发信需要能出到 SMTP 服务器 |
| 显示器 | 1024×768 及以上（登录/领用与计划/邮件设置窗口按 1024×768 设计） |

## 3. 部署步骤

1. **解压到纯英文路径**，例如 `C:\ORT-XP`。
   > 硬性要求：路径里不能有当前 ANSI 代码页表示不了的字符。XP 繁体（cp950）机器上放简体字目录，
   > 导入 tkinter 时就会失败。程序启动会自检并在这种路径上给出提示（退出码 2），不会静默失败。
2. 把数据文件夹准备好：
   - 共享目录先映射成盘符（例如 `Z:`），再指向 `Z:\...\Data`；
   - 或者把 `ort_plans.db` 直接拷到 `C:\ORT-XP\Data\`（只适合单机试用：两端各写各的副本会分叉）。
3. 双击 `ORT-XP.exe`：首次运行会弹出「没有找到数据库」，点 **是** 选择数据文件夹
   （选到 `...\bin\Debug` 也行，程序会自己往下找一层 `Data`）；选中后写入
   `C:\ORT-XP\Data\local_settings.json`，下次直接进登录窗口。
4. 双击 `make_shortcut.vbs` 在桌面建快捷方式（XP 默认没有 PowerShell，所以用 WSH）。
5. 双击 `selftest.cmd` 做一次现场自检（见下一节）。自检通过后即可交付使用。

## 4. 现场自检与排错

`selftest.cmd` 会依次跑四件事，然后把日志用记事本打开：

| 命令 | 作用 |
| --- | --- |
| `ORT-XP.exe --version` | 确认程序能起来（能打印版本说明 DLL 都加载成功） |
| `ORT-XP.exe --selftest` | 14 项环境自检：解释器、SQLite、**TLS 1.2 能力**、DPAPI、数据库、关键表、账号可读、设置可读、邮件配置 |
| `ORT-XP.exe --ui-smoke` | 界面装配自检：造出登录窗口/主窗口/页签/表单/邮件/自检窗口，并逐个确认**真的显示出来** |
| `ORT-XP.exe --check-plans-email` | 计划到期提醒演练（**不发信**），列出候选计划与跳过原因 |

排错顺序：

1. 看 `C:\ORT-XP\Logs\ort_xp.log`：**所有启动期失败都会留 `[ERROR]` 行**（缺数据库、路径不可编码、
   tkinter 装不起来、数据库打不开、邮件校验失败……），无界面命令的结果也写在这里。
   日志是 UTF-8 **带 BOM**，XP 记事本直接打开不会乱码。
2. 看 `C:\ORT-XP\Logs\fatal_*.log`：真正崩在异常上的完整回溯（同时会弹原生消息框）。
3. 想让脚本自己跑、不要弹框：加 `--no-dialog`（或设环境变量 `ORT_XP_NO_DIALOG=1`）。
4. 「双击没反应」几乎只有三种原因，日志里都能看到：数据文件夹里没有 `ort_plans.db`、
   程序放在含简体中文的目录、缺 DLL（用 `--version` 就能区分）。

## 5. 已知限制（交付时必须告知使用方）

**范围内不做**（详见 [00-范围与验收.md](00-范围与验收.md) 的 Out 清单）：

- 报告生成全链路（Excel/Word 模板、OLE 嵌入、Word→PDF）、报告链接与文件夹扫描、计划索引；
- 审核流与流程状态、回线/入库/报废登记窗口、领退↔计划互转；
- 管理端：用户管理、测试项与目录维护、`test_plans` / `plan_item_templates`；
- 界面体系：多语言、主题、UI 缩放、Toast、更新日志窗口；列筛选多级合并、列宽/列序记忆、拖拽排序；
- 与审核相关的邮件通知。

**功能上与主程序的差异**：

| 差异 | 影响 |
| --- | --- |
| 没有审核提交 | XP 端的改动**直接落库**并写变更日志；主程序会看到这些改动 |
| 收件人分隔符更多（「，」「、」「/」） | 主程序不拆斜杠，真实库里 187 条计划的负责人写成 `李剛/李志斌`，主程序侧这些提醒发不出去；XP 端能正确拆开 |
| 邮件口令存本机 | XP 端**不写** `mail.passwordEnc`（主程序那台机器的 DPAPI 密文），首次使用要在邮件设置里存一次本机口令 |
| 邮件模板与抄送管理员开关只读 | 由主程序设置窗口维护，XP 端不覆盖 |
| 到期提醒由谁定时发送 | **必须约定只有一端负责**（`DedupeDays` 只能兜底、且同一瞬间并发仍可能重发）。客户端**默认不发定时信**；要启用由 XP 端负责，见第 7 节 |

**运行前提（现场常见坑）**：

- 6 个账号的 `Email` 目前都是空的 → 提醒与通知邮件**发不出去**，需要在主程序里补邮箱；
- 计划「负责人」要能解析成邮箱：填显示名/登录名都行，多个用分隔符隔开；
- 共享目录上的 SQLite：不要用 UNC 路径，映射盘符；两端同时写库时短事务 + 忙等待会重试，但仍建议
  不要长时间并发编辑同一条记录；
- XP 的系统根证书库已过期：需要证书校验时把 `cacert.pem` 放到 `ORT-XP\` 或 `ORT-XP\ca\`；
  内网自签名服务器可在邮件设置里显式勾「忽略证书错误」。

## 7. 定时提醒（可选，默认关闭）

客户端**不会自己定时发信**：不装计划任务、不后台定时，除非你显式启用。启用的方式是让 XP 的计划任务
按天调用包内的 `reminder.cmd`：

```
reminder.cmd
  → ORT-XP.exe --check-plans-email --send --no-dialog        （真的发信）
  → Logs\reminder.log 追加两行：开始时间 + 退出码
  → 逐条明细（哪个工令发给了谁、为什么跳过）在 Logs\ort_xp.log
```

退出码：`0` = 这一轮没有失败；`1` = 至少一封发失败（去看日志）。手工验证时可以先不加 `--send`
跑一次演练（只列候选计划与跳过原因，不发信）。

### 7.1 与主程序的分工（关键）

两端共用同一份 `mail_logs` 去重记录（`Kind=Warning`、`RefType=Plan`、`RefKey=工作編號`），
主程序的到期提醒也是这么去重的，所以：

- **`去重天数 ≥ 1`（默认 1）时，两端都开着也不会重复发信**：先发出去的一端写了记录，另一端在去重
  窗口内会跳过，提醒明细里会写「去重：N 天内已对 Plan/<工令> 发过同类邮件」。
- `去重天数 = 0` 会关掉这层保护 → 两端都跑就各发一封。邮件设置界面在「警告类邮件开着 + 去重填 0」时
  会给出警告。
- 唯一的竞态窗口是两端**同一瞬间**开始发送（两边都还没写记录）。避免办法：把两端的执行时间错开
  （例如主程序白天有人开机、XP 定在早上 8:00），或只让一端负责。

现场怎么拍板：

| 现场情况 | 建议 |
| --- | --- |
| 主程序所在机器长期有人开机 | **由主程序负责**；XP 端不建计划任务，只保留界面上的「到期提醒演练」按钮 |
| 主程序不常开、XP 机器是唯一常开的 | **启用 XP 的定时任务**（第 7.2 节）；`去重天数` 保持 ≥ 1，两端共存也安全 |

### 7.2 在 XP 上创建计划任务

XP 自带「任务计划」（控制面板 → 任务计划 → 添加任务计划，按向导选 `reminder.cmd`、每天、指定时间）；
XP Professional 也可以用命令行：

```bat
rem 每天 08:00 执行一次（按实际部署路径改）
schtasks /create /tn "ORT-XP reminder" /tr "C:\ORT-XP\reminder.cmd" /sc daily /st 08:00 /ru <用户名> /rp <口令>
```

注意事项：

- **「起始位置」填 `C:\ORT-XP`**（或直接用上面的完整路径调用 `reminder.cmd`，脚本自己会切目录）。
- **必须用「保存过 SMTP 口令的那个 Windows 账户」运行任务**：口令是用 DPAPI(CurrentUser) 加密存在
  `%LocalAppData%` 下的，换账户解不开 → 会变成「没有口令」而发信失败。所以不要用 `SYSTEM`，
  也不要换管理员账户。
- **用固定用户账户，不要用 `SYSTEM`**：SYSTEM 账户看不到映射的网络盘符，而数据文件夹常常是映射盘
  （SQLite 打不开 UNC 路径）。建好任务后先用该账户手工双击一次 `reminder.cmd` 确认能读到库。
- 计划任务跑起来是**没有窗口**的，结果只看 `Logs\reminder.log` 与 `Logs\ort_xp.log`。
- 数据文件夹在网络共享上时，要保证该用户在登录/未登录状态下都能访问（映射盘符需要在
  「该用户的登录会话」里存在；必要时改用固定盘符映射或在任务里先 `net use`）。
- 想跑得更勤也可以（例如每 2 小时）：`DedupeDays ≥ 1` 时同一天只会真正发一次，之后都走去重跳过。

### 7.3 数据文件夹：不要留两份副本

XP 端的 `C:\ORT-XP\Data\local_settings.json` 指向哪个文件夹，它就读写哪个库。**不要把主程序的
`Data` 目录整个拷一份放到 `C:\ORT-XP\Data` 当成 XP 专用副本**：两端各写各的副本，很快就分叉，
主程序看不到 XP 端的改动（XP 端也看不到别人的）。

- 正确做法：指向**同一个**共享数据文件夹（映射成盘符），两端读写同一份库；
- 单机试用（XP 端与主程序在同一台机器）：指向主程序的 `Data` 目录；
- 真要拷贝副本：**先把主程序关掉**再拷（`ort_plans.db` 处于 WAL 模式时，未检查点的事务在
  `-wal` 文件里；只拷 `.db` 会丢掉最近改动；保险起见连 `-wal`、`-shm` 一起拷）。
