# 01 · 环境搭建

## 1. 目标机（XP 机器）环境

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows XP SP3，32 位 | 低于 SP3 装不了 .NET 4.0，也不在支持列表 |
| 解释器 | **Python 3.4.4（32 位）** | XP 上可用的最后一个 CPython 系列是 3.4；3.4.5 之后 python.org 只发源码包，带 Windows 安装包的最后一版是 3.4.4 |
| 运行库 | MSVCR100（VS2010 CRT） | 3.4 自带依赖，XP 可用；3.5+ 改用 UCRT，XP 上不可用 |
| 打包器 | **PyInstaller 3.3.1**（3.3.1–3.4 均可） | 3.3.1 是官方明确“重新支持 XP 目标”的版本；现代版本要求 Win8+ |
| 产物形态 | **onedir**（非 onefile） | onefile 每次启动解压到 %TEMP%，XP 上慢且易被杀软误报 |
| Office | 不需要 | 本范围不碰 Excel/Word/PDF |
| 网络 | 出站 25/587/465 到邮件服务器 | 走 Python 自带 OpenSSL，不依赖系统 Schannel |

## 3. 开发策略

1. **用本机 3.13（32 位）写代码**，但源码必须保持 **Python 3.4 语法**；
   用 `tools/compat_check.py` 卡住下限（零依赖的 AST 扫描，可单独跑，也被 `check_env.py` 与单测调用）。
2. **打包只能在 Python 3.4 环境做**（PyInstaller 3.3.1 是 3.4 时代的产物）。
   两种做法：
   - 装一个 Python 3.4（32 位）在本机，只用于打包；
   - 或在 XP 虚拟机里装 Python 3.4，直接在目标系统上打包（最稳，也顺带做回归）。
3. 代码里**不使用**虚拟环境与第三方包（本范围零依赖），因此不存在跨解释器依赖解析问题。

## 4. Python 3.4 语法与 API 约束

`tools/compat_check.py` 会拦住下列写法，写代码时直接避开：

| 禁止 | 引入版本 | 替代写法 |
| --- | --- | --- |
| f-string（`f"{a}"`） | 3.6 | `"{}".format(a)` 或 `%` |
| 变量/函数注解（`x: int`、`def f(x: int) -> str`） | 3.5 / 3.6 | 写在 docstring 里 |
| `async` / `await`、`async def` | 3.5 | 本范围用线程或同步即可 |
| `typing` 模块 | 3.5 | 不用类型标注 |
| `dataclasses` | 3.7 | 普通 class + `__init__` |
| 海象运算符 `:=` | 3.8 | 普通赋值 |
| `secrets` 模块 | 3.6 | `os.urandom` + `binascii` |
| `os.scandir`、`os.fspath` | 3.5 | `os.listdir` 递归（`compat.walk_files`） |
| `subprocess.run(capture_output=)`、`encoding=` | 3.7 | `Popen` + `communicate()` |
| `subprocess.run(text=)` | 3.7 | 手动 decode |
| 字典合并 `a | b`、`str.removeprefix` | 3.9 | `dict(a, **b)`、切片 |
| `logging.FileHandler(encoding=)` | 3.9 | `codecs.open` + `logging.StreamHandler`（`logging_setup.py` 已封装） |
| `math.isclose` | 3.5 | 手写比较 |
| `datetime.fromisoformat` | 3.7 | `datetime.strptime`（`compat.parse_datetime_text`） |

允许并已在用：`enum`（3.4 起）、`pathlib`（3.4 起）、`asyncio`（3.4 起）、`unittest.mock`、
`json`、`sqlite3`、`tkinter`/`ttk`、`ssl.SSLContext`、`smtplib`、`ctypes`、`uuid`、`argparse`。

## 5. 安装打包用的 Python 3.4（脚本：`tools/install_py34.ps1`）

**关键事实**：`python-3.4.10.exe` **不存在** —— 3.4.5 之后 python.org 只发源码包，
最后一个带 Windows 安装包的 3.4 版本是 **3.4.4**（`python-3.4.4.msi`，32 位，约 24 MB）。
XP 支持由 3.4 系列本身决定（同一条 VS2010 CRT 工具链），用 3.4.4 打 XP 包没有问题。

**做法（已在本机执行）**：用 **MSI 管理安装**把 3.4.4 解包到 `D:\Python34-32`：

```powershell
.\tools\install_py34.ps1                        # 下载 + 解包 + 装 pip/PyInstaller
.\tools\install_py34.ps1 -TargetDir D:\Py34     # 换目录
.\tools\install_py34.ps1 -SkipPyInstaller       # 只要解释器
```

脚本的内部动作（也可以手工执行）：

1. 下载 <https://www.python.org/ftp/python/3.4.4/python-3.4.4.msi>
2. `msiexec /a python-3.4.4.msi /qn TARGETDIR=D:\Python34-32`
   —— **管理安装**：只解包文件，**不写注册表、不改 PATH、不动系统里其它 Python**，也不需要管理员权限；
   打包只需要一个能跑的 `python.exe`。
3. `python.exe -m ensurepip` → `-m pip install "pip<19.2"`（3.4 的 pip 上限是 19.1.1）
4. `-m pip install "pyinstaller==3.3.1"`（PyInstaller 3.3.1 起才重新支持 XP 目标的启动器）
   —— Python 3.4 的 `ssl` 不读 Windows 证书库，装包要加 `--trusted-host pypi.org --trusted-host files.pythonhosted.org`。
5. 校验：

```powershell
D:\Python34-32\python.exe -c "import sqlite3, ssl, tkinter, smtplib; print(sqlite3.sqlite_version, ssl.OPENSSL_VERSION)"
D:\Python34-32\python.exe -m PyInstaller --version     # 期望 3.3.1
```

装好后跑一遍本项目的测试与打包：

```powershell
D:\Python34-32\python.exe -m unittest discover -s tests -v   # 在 3.4 下验证代码兼容性
.\tools\build_xp.ps1 -Python D:\Python34-32\python.exe
```

### 安装过程踩过的三个坑（脚本已处理）

1. **没有 `python-3.4.10.exe`**：3.4.5 之后 python.org 只发源码包，带 Windows 安装包的最后一版是
   **3.4.4**（`python-3.4.4.msi`，24.9 MB，签名者 Python Software Foundation）。
2. **MSI 管理安装不会解出 CRT**：MSI 里 `SharedCRT` / `PrivateCRT` 是 merge module 特性，
   `msiexec /a` 默认特性集不含它们，解包出来的 `python.exe` 一运行就以 `0xC0000135`
   （STATUS_DLL_NOT_FOUND）退出。`install_py34.ps1` 会在本机找一份**32 位且带 Microsoft 有效签名**的
   `msvcr100.dll` 补进目标目录（本机取自 `C:\Program Files (x86)\D-Security\vc10\x86\msvcr100.dll`）。
   这一条对最终交付同样重要：XP 机器也可能没有 VC++2010 运行库，**发布包里必须带上 msvcr100.dll**。
3. **含中文的 `.ps1` 必须存成 UTF-8 with BOM**：Windows PowerShell 对无 BOM 的脚本按 ANSI（本机 cp950）
   解析，中文多字节序列会被拆坏，直接语法报错。`tools/*.ps1` 都已带 BOM（改这些脚本后请保持）；
   `packaging/ort_xp.spec` 与 `packaging/entry_xp.py` 则刻意只写 ASCII。
4. **程序目录必须是纯 ASCII 路径**：Windows 下模块加载器用 ANSI 代码页编码路径。本机 cp950（繁体）
   编不了简体字，仓库名「ORT一键报告」里的「键/报」于是让**打包后的程序**在导入 tkinter 时抛
   `UnicodeEncodeError`（窗口子系统只弹框、不打印，看起来像卡死，实际写进了 `Logs\fatal_*.log`）。
   处理办法：
   - 打包：`tools/build_xp.ps1` 自动在 `%TEMP%\ort-xp-build`（纯 ASCII）里构建，再拷回仓库；
   - 运行/部署：程序启动时会检查路径，编不了就弹框提示并把退出码置 2（`--selftest` 时直接打印）。
     部署到 XP 时请用 `C:\ORT-XP` 这类纯英文路径。
   - 注意 Python 3.6+ 的 Windows 文件系统编码是 UTF-8，所以**开发机 3.13 上不会出现这个问题**，
     只有 3.4（mbcs）与打包后的程序才会 —— 别在 3.13 上验证就以为没事。

## 6. 打包器备选方案（若 PyInstaller 3.3.1 走不通）

按优先级：

1. **直接分发解释器目录**：把 `D:\Python34-32` 整个目录拷到 XP 机器，
   用 `pythonw.exe ort_xp` 或一个 `.bat` 启动。没有任何启动器兼容性风险，代价是体积（约 30 MB）。
2. **cx_Freeze 5.1**：同样支持 Python 3.4 时代的构建，可作第二个启动器实现。
3. **退回 .NET net40 方案**：只有在“邮件可以放弃”时才考虑（net40 在 XP 上没有 TLS 1.2）。

## 9. 首次运行与「启动期故障可见」（2026-10-07 实机反馈后的修复）

### 现场

把 `dist\ORT-XP` 拷到 `C:\ORT-XP` 后双击，日志里只有两行就没反应了：

```
14:08:58 [INFO] ort_xp: 启动：... v0.2.0
（此后什么都没有，也没有界面、没有弹框）
```

### 根因

1. 打包后的 exe 是**窗口子系统**：没有控制台，`sys.stderr` 是 `None`。
   `compat.say_err()` 往 `None` 上写等于什么都没写，`except` 分支于是「静默返回 2 退出」。
2. `C:\ORT-XP\Data` 不存在（发布包里不含数据库）→ `Database.connect()` 抛「数据目录不存在」。
3. 更隐蔽的一条：**只要 `Data` 目录存在但里面没有 `ort_plans.db`，sqlite 会顺手建一个空库**，
   于是程序「启动成功」，接着在登录/取数时抛一堆看不懂的错。
4. 修完上面三条后仍然「进程活着、屏幕上一个窗口都没有」：登录窗口是 `tk.Toplevel` 且调用了
   `transient(parent)`，而**父窗口（主窗口根窗口）此时是 withdraw 状态** —— Tk 在 Windows 上会把
   master 已隐藏的 transient 窗口一起保持隐藏。实测（Tk 8.6，3.4 与 3.13 两个解释器都一样）：

   ```
   transient=False master_visible=False -> mapped=1 viewable=1
   transient=True  master_visible=False -> mapped=0 viewable=0    ← 症状
   transient=True  master_visible=True  -> mapped=1 viewable=1
   ```

   所以登录窗口永远等不到人点，`wait_window()` 一直挂着：进程活着、响应中、没有任何窗口。

### 修复

| 改动 | 说明 |
| --- | --- |
| 启动期失败统一走 `ort_xp/fatal.py::report()` | 写 `Logs\ort_xp.log`（`[ERROR]`）+ 弹原生消息框，框里给出数据文件夹、库路径、日志位置 |
| 首次运行选择数据文件夹（`ort_xp/ui/first_run.py`） | 提示框 → 目录选择对话框；选中 `<目录>` 或 `<目录>\Data` 里有 `ort_plans.db` 即通过，写进 `<程序目录>\Data\local_settings.json` 后继续启动 |
| 缺库不再「连一个空库」 | 启动时先 `database.exists()`，不存在就报错/选库，绝不放行 |
| `--no-dialog`（环境变量 `ORT_XP_NO_DIALOG=1`） | 出错只写日志不弹框；`--selftest` / `--ui-smoke` / `--check-plans-email` 自动等同于此，避免脚本被消息框卡住 |
| `--ui-smoke` | 无人值守的界面装配自检：造出登录窗口/主窗口/页签/领用和计划窗口/表单/邮件与自检窗口，**并逐个确认 `winfo_viewable()` 为真**，退出码 0/1；目标机上用它证明界面真能显示出来（只查「造得出来」是查不出上面第 4 条的） |
| 登录窗口不再 transient 到隐藏的主窗口 | 见根因 4；主窗口显示后再弹出的窗口（表单、邮件、自检、领用和计划）不受影响，保持 transient |
| `build_xp.ps1` 第 6 步 | 构建后在 ASCII 暂存路径里真跑一次 `ORT-XP.exe --version`，退出码非 0 就构建失败 |

排错顺序：先看 `ORT-XP\Logs\ort_xp.log`；崩在 `sys.excepthook` 上的看 `Logs\fatal_*.log`。
无界面命令（`--selftest` / `--ui-smoke` / `--check-plans-email`）的输出也会写进这个日志，
双击启动时没有控制台，日志才是能看到的现场。
