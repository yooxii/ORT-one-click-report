**里程碑 1 · 技术验证（2026-10-07，本机部分）**

- 装好打包用解释器：`D:\Python34-32` = Python **3.4.4**（32 位，3.4 系列最后一个带 Windows 安装包的版本；
  3.4.10 只有源码）。用 MSI 管理安装 + 补齐 32 位 `msvcr100.dll`，全过程脚本化（`tools/install_py34.ps1`）
- 装好 **PyInstaller 3.3.1**（依赖锁 `pefile==2017.11.5 / altgraph==0.16.1 / pywin32-ctypes==0.2.0`，
  新版依赖用了 3.6+ 语法装不上）
- **Python 3.4.4 下测试全绿**：66 项单测通过、语法下限 0 处问题（此前只在 3.13 下验证过）
- 打出 XP 包 `dist\ORT-XP`（15.3 MB / 917 文件）：启动器 PE 头 `MajorOperatingSystemVersion = 5.1`
  （面向 XP），包内带 32 位 Microsoft 签名 `msvcr100.dll`、tcl/tk、sqlite3
- 包在本机实测：`--version`、`--selftest`（14 项全通过：Python 3.4.4/32 位、OpenSSL 1.0.2d +
  PROTOCOL_TLSv1_2、DPAPI 往返、真实库 20 张表 / 6 账号 / 35 设置键）、
  `--check-plans-email` 演练（68 条候选计划）全部退出码 0
- 期间修掉四个只能在打包/3.4 上暴露的问题：
  1. PyInstaller 3.3.1 用 ANSI 编码读写 spec → spec 改为**纯 ASCII**；
  2. 同样的 ANSI 编码问题会因**仓库路径含中文**在构建时崩 → 构建改为在 `%TEMP%` 的 ASCII 暂存目录进行；
  3. 打包入口不能用包内的 `__main__.py`（相对导入失效）→ 新增包外入口 `packaging/entry_xp.py`；
  4. **程序目录含 ANSI 编不了的字符时**（本机 cp950 + 简体「一键报告」），导入 tkinter 会以
     `UnicodeEncodeError` 崩掉且只弹框不打印 → 启动前加路径检查，给出人话提示并以退出码 2 结束
- 顺带增强：顶层异常兜底（写 `Logs\fatal_*.log` + 原生弹框）、tkinter 回调异常同样兜底、
  重定向输出时中文按 UTF-8 写（窗口子系统日志不再变转义字符）

## 3. 风险与替代

| 风险 | 影响 | 应对 / 替代 |
| --- | --- | --- |
| PyInstaller 3.3.1 在 XP 上跑不通 | 阻塞交付形态 | 备选：直接分发 Python 3.4 目录 + `.bat` 启动；或 cx_Freeze 5.1 |
| 没有 XP 实机/虚拟机 | 无法验证里程碑 1 | 先装 VirtualBox 建 XP SP3 虚拟机；本机目前无虚拟化软件 |
| Python 3.4 的 pip/PyPI 访问受限 | 打包机装不上 PyInstaller | 用离线 wheel/源码包安装；本范围运行时零依赖，只有打包器需要 |
| 邮件密码 DPAPI 跨机器解不开 | XP 端发信失败 | 本机口令文件（DPAPI 加密）+ 设置界面填写；README §7 |
| 双客户端同时写库 | 锁等待、偶发失败 | 短事务 + busy_timeout 30 s + 指数退避重试；不改 journal_mode |
| XP 上 CA 根证书过期 | SMTP/HTTPS 证书校验失败 | 随包分发 PEM，运行时可 `cafile` 指定；忽略证书错误需显式开关 |
| 范围蔓延（“顺便把报告也做了”） | 工时成倍增长 | 以 docs/00 的 In/Out 为准，新增需求重新估工时 |

## 4. 决策记录

| 日期 | 决策 | 理由 |
| --- | --- | --- |
| 2026-10-07 | 用 Python + 标准库实现，不用 .NET 降级到 net40 | XP 的 Schannel 只到 TLS 1.0，net40 无法 TLS 1.2 发信；邮件是范围内的硬需求 |
| 2026-10-07 | 运行时零第三方依赖 | 范围已排除 Excel/Word/PDF/OLE，标准库足够；XP 上无需再找 cp34 的 wheel |
| 2026-10-07 | 用 onedir 而非 onefile | onefile 每次解压到 %TEMP%，XP 上慢且易被误报 |
| 2026-10-07 | 表结构由主程序负责，XP 端只读写不建表 | 避免两套迁移逻辑打架（FreeSql `UseAutoSyncStructure`） |
| 2026-10-07 | 开发机用 3.13 写代码 + `compat_check.py` 卡 3.4 语法 | 本机没有 Python 3.4；目标是“代码能跑在 3.4”，检查器比人工记忆可靠 |
| 2026-10-07 | 邮件提醒定时只由一端负责（待与主程序约定） | 两端都跑会重复发信 |
