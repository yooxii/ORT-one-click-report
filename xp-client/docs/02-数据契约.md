# 02 · 数据契约（与主程序共库的约定）

XP 客户端与主程序 .NET 版**共用同一份数据**。本文件记录全部接口约定，
所有取值都已在主程序真实数据库上核对过（`bin\Debug\Data\ort_plans.db`，2026-10-07）。

## 1. 数据目录怎么定

主程序（`Services/PathService`、`Services/DatabaseService`）：

1. 程序目录 `Data\local_settings.json` 里的 `DataFolder`（可以是 UNC：`\\服务器\共享\目录`）
2. 为空 → 程序目录 `Data`

XP 客户端按同样的顺序解析，额外支持一个环境变量，便于运维与排错：

```
ORT_XP_DATA_FOLDER  →  local_settings.json 的 DataFolder  →  <程序目录>\Data
```

XP 客户端使用**自己的** `Data\local_settings.json`（键名与主程序完全一致：
`DataFolder` / `AteDataPath` / `EmiDataPath`），便于把配置文件直接抄过来。

数据库文件名固定：`<DataFolder>\ort_plans.db`。

### UNC 路径限制

SQLite **不能直接打开 UNC 路径**（主程序在 `DatabaseService` 里也是先把 UNC 映射成盘符再开库）。
XP 客户端同样处理：检测到 `\\` 开头的路径时，先尝试用 `WNetAddConnection2`（ctypes 调 `mpr.dll`）
映射盘符；映射失败就明确报错并提示改用盘符路径。**不使用 `net use` 外部命令**（XP 上交互与凭据问题多）。

## 2. 连接与并发

| 项 | 取值 | 来源 |
| --- | --- | --- |
| 连接串要点 | `Pooling` 忽略（Python 侧自建连接），超时 30 s | `DatabaseService` |
| 忙等待 | `PRAGMA busy_timeout=30000` | 主程序启动时设置 |
| 日志模式 | 本地盘 `WAL`；网络共享 `TRUNCATE` + `synchronous=FULL` | 主程序按是否网络路径切换 |
| WAL 注意 | WAL 依赖共享内存，SMB 上不可用 | 主程序注释与 `SqliteFileUtil` |

**XP 客户端的做法**：启动时只 `PRAGMA journal_mode` 读一下当前模式并记录日志，
**绝不主动改**——改了会与主程序抢锁。若发现“网络路径 + WAL”这种危险组合，直接提示用户。

写操作统一走短事务，遇 `database is locked` / `database table is locked` 指数退避重试（默认 5 次，总时长 ≈ 30 s）。

> 两个客户端同时写同一个库是允许的（SQLite 的多进程锁模型），但**不要长事务**。

## 3. 日期与布尔值格式（实测）

主程序用 System.Data.SQLite，日期以 **TEXT** 存储，实测两种形态：

```
'2026-09-01 00:00:00'              # 日期/普通时间戳
'2026-09-29 11:29:17.806635'       # DateTime.Now 带微秒（最多 7 位小数）
```

- 读取：两种都要能解析（`compat.parse_datetime_text`）。
- 写入：一律用 `yyyy-MM-dd HH:mm:ss`（不带微秒），与主程序的日期字段一致。
- 比较：同格式下字符串比较等价于时间比较，可按 `EndDate <= '2026-10-10 00:00:00'` 直接过滤。

布尔值：SQLite 里是 `BOOLEAN`（底层 INTEGER 0/1）；但**设置表里的布尔是文本**，且是 .NET 风格：

```
'True' / 'False'      ← app_settings.Value
```

解析统一用 `compat.to_bool()`（兼容 `True/False/true/false/1/0/yes/no`）。

### 邮件模板占位符

主程序模板语法是 `{{变量}}`，支持格式化后缀 `{{EndDate|yyyy/M/d}}`。
XP 客户端内置相同的渲染器（`services/mail.py` 的 `render_template`），
支持 `yyyy yy MM M dd d HH H mm m ss s` 这些 .NET 格式符。

## 6. 登录

```
PasswordHash = Base64( SHA256( UTF8( Salt + Password ) ) )     Salt = Guid.NewGuid().ToString("N")
```

- `Salt`：32 位小写十六进制（Python：`uuid.uuid4().hex`）。
- 校验规则（`AuthService.Login`）：
  1. `Username` **精确匹配**（大小写敏感）；
  2. `IsActive` 必须为真；
  3. `PasswordHash` 与 `Salt` 都非空 → 比对散列；都为空 → **用户名对即放行**（无密码账号）；
  4. 角色取自 `user_roles.Role`（可识别的值形如 `Administrator`）。

Python 侧实现见 `ort_xp/services/auth.py`，两者对同一份库必须互相认。

### 记住登录

- 主程序：`%LocalAppData%\ORT实验室管理系统\login.json`（密码 DPAPI CurrentUser 加密）。
- XP 客户端：`%LocalAppData%\ORT实验室管理系统-XP\login_xp.json`，**故意分文件**，
  避免与主程序互相覆盖；格式自定，密码同样 DPAPI 加密。

## 7. 邮件密码的特殊处理（重要）

主程序把 SMTP 密码用 **DPAPI(CurrentUser)** 加密后写进共享库的 `mail.passwordEnc`。
DPAPI CurrentUser 的密钥绑定“当前用户 + 当前机器”，因此：

- 在 A 机器 A 用户加密的口令，B 机器/B 用户**解不开**；
- 即主程序自己换机器也解不开（这是现有实现的既有限制，不是 XP 客户端引入的）。

XP 客户端策略（按优先级）：

1. 读共享库 `mail.passwordEnc`，尝试用 ctypes 调 `CryptUnprotectData` 解密（同机同用户才可能成功）；
2. 解不开或为空 → 使用本机口令文件
   `%LocalAppData%\ORT实验室管理系统-XP\mail_credential.json`（DPAPI 加密），
   在 XP 客户端的“邮件设置”里填写；
3. 两者都没有 → 明确提示“请在邮件设置里填写本机 SMTP 密码”，**不静默失败**。

另外：`mail.useDefaultCredentials = True`（Windows 集成验证）在 XP 客户端**不支持**
（Python 标准库没有 NTLM），检测到该开关时给明确提示。

## 8. 变更日志（必须写）

主程序的审核模块依赖 `plan_change_logs`。XP 客户端每一次对 `plans` / `requisitions` 的写入
都必须留一条记录（结构见 schema.md），否则主程序看不到 XP 这边的改动。

字段取值约定：`CreatedBy` / `UpdatedBy` 写当前登录用户名，时间写 `yyyy-MM-dd HH:mm:ss`。
